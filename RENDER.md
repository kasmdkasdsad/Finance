# QuantPulse on Render — the Brain 24/7 with your PC off

**Paper trading only.** QuantPulse can only trade Alpaca's *paper* account (simulated money). The cloud
deployment refuses to start unless that is verifiably true, and no setting points it at a live account.

```
 iPhone ──HTTPS──► quantpulse-dashboard (free; password login)
                          │  private network, API token (your browser never sees it)
                          ▼
                   quantpulse-api  (always on, 1 CPU / 2 GB, exactly one instance)
                   ├─ the QuantPulse API (/health, /api/v1/…, token required)
                   ├─ the Brain supervisor: pre-market checks, cycles every 30 min in the session, quote monitor,
                   │  reconciliation every 5 min, near-close review, close, grading, learning, reviews
                   └─ background jobs: health checks and alerts every minute, the stock model, predictions
                          │                                  │
                          ▼                                  ▼
                   quantpulse-db (PostgreSQL 16,       Alpaca PAPER API
                   private network only)               https://paper-api.alpaca.markets
```

Every Brain order still takes the one path it always has: Brain → agents → consensus/debate → planner → portfolio
fit → risk preview → audit/gates → the trading service → the risk engine → the order manager → Alpaca paper →
reconciliation → the execution ledger → learning/evaluation. The cloud adds no risk engine and no order path.

## Services and monthly cost

| Service (render.yaml) | Render type · plan | What it does | Monthly |
|---|---|---|---|
| `quantpulse-api` | Web service · `1c-2g` (1 CPU, 2 GB) | API + Brain supervisor + background jobs, always on | $25 |
| `quantpulse-dashboard` | Web service · `free` | The Streamlit dashboard (sleeps after 15 idle minutes; wakes in ~1 minute) | $0 |
| `quantpulse-db` | Postgres 16 · `0.1c-256mb`, 5 GB disk | Every cycle, opinion, decision, order, fill, thesis, evaluation, event | $6 + $1.50 disk |
| | | **Total** | **≈ $32.50** |

Why 2 GB and not the $7 512 MB instance: the stock model (the S&P 500, point-in-time, as on your PC) peaks at
about **1.5 GB** while it trains (measured); on 512 MB it would be killed mid-run. The API and a Brain cycle alone
need about 335 MB. If you want to try ~$14/month, set `plan: 0.5c-512mb` *and* `QP_MODEL_UNIVERSE=picks` (the
model then covers 30 stocks, with survivorship bias) — a real trade-off, so it is not the default.

Why one service for the API and the Brain: a paid Render web service never sleeps, so the supervisor runs inside
it; a separate worker would cost another 2 GB instance and split state that is simpler kept together. A
database lease guarantees one supervisor anyway — including the minute or two of every deploy when Render runs
the old and the new instance side by side.

Prices as published by Render in September 2026. Paid instances need a payment method on your Render account.

## Environment variables

Set by `render.yaml` (you do not type these):

| Variable | Value | Why |
|---|---|---|
| `QP_DEPLOYMENT` | `cloud` | enforces the paper-only preflight, the token on every request, JSON logs |
| `QP_ALPACA_PAPER` | `true` | paper only (anything else does not even load) |
| `QP_BRAIN_MODE` | `paper_execution` | the Brain owns the paper account (required in the cloud) |
| `QP_ALPACA_TRADING_ENABLED` | `true` | orders may be sent — after every other gate passes |
| `QP_TRADING_DRY_RUN` | `false` | paper execution (never live: there is no live path) |
| `QP_BRAIN_KILL_SWITCH`, `QP_TRADING_KILL_SWITCH` | `false` | the environment-level kill switches (a second layer) |
| `QP_TRADING_SCHEDULER_ENABLED` | `false` | one scheduler: the Brain supervisor (the old strategy is a shadow) |
| `QP_TRADING_SCHEDULER_REQUIRES_ARMING` | `true` | scheduled orders wait for the Brain's pre-trade audit |
| `QP_BRAIN_SUPERVISOR_ENABLED`, `QP_POLLING_ENABLED`, `QP_ENABLE_LIVE_DATA` | `true` | the Brain runs by itself on live data |
| `QP_ALPACA_STOCK_FEED` | `iex` | the free feed (`sip` later, with a subscription) |
| `QP_AUTO_MIGRATE` | `false` | migrations run once per deploy (pre-deploy), never from two instances |
| `QP_LOG_JSON`, `QP_LOG_LEVEL` | `true`, `INFO` | structured logs, searchable in Render |
| `QP_SHUTDOWN_DRAIN_SECONDS` | `75` | a cycle running at a deploy may finish before hand-over (it sends no new order) |
| `QP_DATABASE_URL` | from `quantpulse-db` | automatic (internal address) |
| `QP_API_TOKEN` | generated by Render | **secret**; the dashboard receives it automatically |

You enter these once, when Render asks (never in Git, never in a file):

| Service | Variable | Secret? | Example / note |
|---|---|---|---|
| quantpulse-api | `QP_ALPACA_API_KEY_ID` | **yes** | your **paper** key id (starts with `PK`) |
| quantpulse-api | `QP_ALPACA_API_SECRET_KEY` | **yes** | your paper secret |
| quantpulse-api | `QP_SEC_USER_AGENT` | no | `Your Name you@example.com` (the SEC asks for contact details) |
| quantpulse-dashboard | `QP_DASHBOARD_PASSWORD` | **yes** | at least 12 characters |

Optional, add later under *quantpulse-api → Environment* (all secrets): `QP_ALERT_NTFY_URL` (phone push alerts via the
free ntfy app), `QP_ALERT_WEBHOOK_URL` (Slack/Discord), `QP_HEARTBEAT_URL` (a free healthchecks.io check: alerts
you if the whole service stops), and any extra data keys you use on the PC (`QP_POLYGON_API_KEY`, …).

Options and market evolution run with their defaults (see [`OPTIONS.md`](OPTIONS.md#8-settings)); nothing needs
to be set. `QP_OPTIONS_EXECUTION=false` keeps options in the shadow book only; `QP_OPTIONS_ENABLED=false` switches the
options layer off; `QP_EVOLUTION_ENABLED=false` stops the daily Market Evolution scan. The option limits
(`QP_OPTIONS_MAX_LOSS_PER_TRADE`, `_MAX_LOSS_PCT_PER_TRADE`, `_MAX_TOTAL_RISK_PCT`, `_MAX_UNDERLYING_RISK_PCT`,
`_MAX_POSITIONS`, `_MAX_CONTRACTS`, `_MIN_DTE`/`_MAX_DTE`, `_MAX_SPREAD_PCT`, `_MAX_QUOTE_AGE_SECONDS`,
`_MIN_OPEN_INTEREST`, `_MAX_DELTA_PCT`, `_MAX_VEGA_PCT`, `_CLOSE_DTE`, `_STOP_LOSS_PCT`, `_EXPLORATION_MAX_LOSS`,
`_ALLOWED_STRUCTURES`) are protected like the share limits:
the cloud refuses to start if one is looser than shipped (a structure can be removed, never added).

Everything else keeps the defaults you run on the PC — including every protected risk control (loss, position,
order, spread, quote-age and data-quality limits). The cloud refuses to start if one of them is set looser.
Database defaults that suit Render (change only if you know why): `QP_DB_POOL_SIZE=5`, `QP_DB_MAX_OVERFLOW=5`,
`QP_DB_CONNECT_TIMEOUT_SECONDS=10`, `QP_DB_COMMAND_TIMEOUT_SECONDS=120`, `QP_DB_STARTUP_WAIT_SECONDS=90` (a
database restarting for maintenance is waited out at start-up instead of crash-looping). `postgres://` and
`postgresql://` URLs are accepted as Render hands them out; an `sslmode=` in the URL is honoured exactly
(`require`, `verify-full`, …) and an unknown mode refuses to start.

## Deploy — step by step in the Render dashboard

1. Sign in at <https://dashboard.render.com> (create an account; connect GitHub when asked, and grant access to the
   `kasmdkasdsad/Finance` repository). Add a payment method (*Billing*).
2. **New → Blueprint**. Pick the repository `kasmdkasdsad/Finance` and the branch **`claude/keen-tesla-y7rion`**.
   Render reads `render.yaml` and lists `quantpulse-api`, `quantpulse-dashboard` and `quantpulse-db`.
3. Fill in the values Render asks for (the table above). **Importing your PC's history?** Type `import-first` as
   `QP_ALPACA_API_KEY_ID` for now — see *Bring your history over* below. Otherwise enter the real paper key.
4. **Apply**. Render creates the database, builds both services (a few minutes), runs the pre-deploy step on the API
   (the paper-only preflight, then the migrations) and starts everything.
5. Open *quantpulse-api → Logs*: you should see `app.startup`, then `supervisor.elected`, then `supervisor.tick`.
   (Outside market hours the ticks say `idle`; the pre-market check runs from 08:30 New York time.)
6. Note the two addresses Render shows: `https://quantpulse-api-….onrender.com` and
   `https://quantpulse-dashboard-….onrender.com`.

That's it: turn the PC off. Every later push to the branch deploys by itself once GitHub CI passes.

### Bring your history over (optional, before the first real start)

Your PC's database (`data\quantpulse.db`) holds the Brain's whole record so far. To move it:

1. Complete steps 1–4 with `QP_ALPACA_API_KEY_ID=import-first`. The pre-deploy preflight fails on purpose (not a
   paper key), so nothing starts and the database stays empty.
2. On the PC, **stop QuantPulse** (the launcher's *Stop*). In PowerShell, in the `Finance` folder:
   ```powershell
   git fetch
   git checkout claude/keen-tesla-y7rion
   git pull
   .venv\Scripts\pip install -e .
   ```
3. Render: *quantpulse-db → Info → Access Control*: add your current IP address. Copy the **External Database URL**
   (it contains the database password: paste it only into your own terminal).
4. On the PC:
   ```powershell
   .venv\Scripts\quantpulse-transfer --source "sqlite+aiosqlite:///data/quantpulse.db" --target '<External Database URL>'
   ```
   Every table is copied and its row count verified.
5. Render: remove your IP from *Access Control* again. Then *quantpulse-api → Environment*: set
   `QP_ALPACA_API_KEY_ID` to your real paper key id → *Save and deploy*. Render redeploys; the preflight passes; the Brain starts
   with its full history.

From then on, keep the Brain off on the PC (or set `QP_BRAIN_MODE=research_only` in its `.env`): two installations
must never trade one account. If one does, the cloud notices QuantPulse orders it did not place and turns its
Brain kill switch on by itself.

## Start and stop autonomous paper trading remotely

| To … | Do this |
|---|---|
| **Stop the Brain now** | Remote → **STOP BRAIN TRADING**. One tap: no new Brain orders, working Brain orders canceled (retried every minute if Alpaca is unreachable). Survives restarts and deploys. |
| Allow it again | Remote → tick *I have looked* → **Allow Brain orders again** |
| A harder stop (only released in Render) | *quantpulse-api → Environment* → `QP_BRAIN_KILL_SWITCH=true` → Save (redeploys) |
| Observe only (no orders at all) | *quantpulse-api → Environment* → `QP_ALPACA_TRADING_ENABLED=false` → Save |
| Pause the supervisor (no cycles) | Brain page → *Supervisor & events* → pause (the API: `POST /api/v1/brain/supervisor {"paused": true}`) |
| Stop everything | *quantpulse-api → Settings → Suspend service* (resume later; the Brain recovers first) |

Without the dashboard (e.g. an iOS Shortcut *Get contents of URL*), with the token from *quantpulse-api →
Environment → QP_API_TOKEN* (it lives only on your phone then):
```
POST https://quantpulse-api-….onrender.com/api/v1/brain/kill-switch
Header  X-API-Key: <token>        Body (JSON)  {"active": true, "reason": "from my phone", "cancel_open_orders": true}
```

## Verify it is running — and PAPER, and alone

From the PC (or anywhere with Python and the repository):
```powershell
$env:QP_CLOUD_URL = "https://quantpulse-api-….onrender.com"
$env:QP_API_TOKEN = "<token from Render>"
.venv\Scripts\quantpulse-cloud-check
```
It prints the version and commit, the supervisor leader and its last tick, Alpaca, the market and whether
autonomous execution is permitted (every reason if not), and ends `OK` or `NOT OK`. Or open
`/api/v1/brain/cloud-status` with the token. What to look for:

* **Running:** `supervisor.last_tick_age_seconds` under ~60–120; `last_result` changes over the day; *Logs* show
  `supervisor.tick`, `brain.cycle` (every 30 minutes in the session), `trading.reconciliation_completed`.
* **PAPER:** `alpaca.paper_endpoint_verified: true` and `endpoint: https://paper-api.alpaca.markets`; the deploy log
  shows the preflight's `[ok] paper_client` and `[ok] paper_key` lines; your Alpaca dashboard shows the orders under
  *Paper Trading*. (A live key cannot work: paper key ids start with `PK`, and the client only talks to the paper API.)
* **Alone:** `supervisor.leader.live: true` with one `holder` (this deploy's instance id); `standby_processes` is empty
  except for a minute or two during a deploy; `numInstances: 1`; each deploy logs exactly one `supervisor.elected`.

## If something goes wrong

* **The service crashed or hangs:** Render restarts it on its own (a failing health check for 60 s, or an exit). The
  new process waits for the old lease (≤ 3 min — never earlier), closes the cycle the old one left running,
  reconciles with Alpaca, recovers positions and working orders, runs the startup audit — and only then trades. You
  get a *Brain supervisor restarted after a crash* alert (the old lease lapsed instead of being handed over).
  Manual: *quantpulse-api* → the menu at the top right → **Restart service**.
* **A deploy failed:** the previous version keeps running (Render only switches on a healthy deploy). The deploy log
  shows why — a `FAIL` line of the preflight, a migration error, or a test that failed in GitHub CI.
* **Roll back:** *quantpulse-api → Events* → a previous deploy → **Rollback**. (If the newer version added a database
  migration, the older code refuses to start on the newer schema — it fails closed; roll the schema back first, or
  roll forward with a fix.)
* **Alpaca or the market data is down:** the Brain holds new orders (health: `alpaca failing`, reconciliation failed,
  stale data → no new buys) and resumes by itself when they answer. Nothing to do.
* **Brain kill switch ON with "automatic: …":** read the reason (repeated rejections, or orders from another
  installation). Fix the cause, then release it on the Remote page.

## Deploying updates safely

Push to `claude/keen-tesla-y7rion`. GitHub CI runs lint, types and the tests (SQLite, plus a PostgreSQL job for
migrations and every cloud/deployment test); only when it passes does Render build, run the preflight and the
migrations once, start the new instance, wait for its health check, then stop the old one. During that overlap
the old instance keeps the supervisor lease; on SIGTERM it takes no new tick and sends **no new order** (one already
on its way completes and is recorded), lets a running cycle finish (up to 75 s), reconciles once more, records a
clean stop, releases the lease, and exits; the new instance takes over within a minute, reconciling and auditing
first, and decides afresh on fresh data. Orders carry
deterministic client ids and are recorded before they are sent, so nothing is sent twice even if a process dies
mid-order. Deploys during market hours are safe; deploying outside them is simply quieter. Keep migrations
additive (the old version runs briefly on the new schema).

### Restart recovery, in order

1. Start; the preflight has already checked the configuration, the paper endpoint and the paper key (it runs as
   the pre-deploy command and again at start-up: the API refuses to start otherwise).
2. The database must answer (waited out for up to 90 s) and its schema must be at this version's head.
3. The supervisor lease: exactly one process leads (the database's clock decides, so instances with skewed
   clocks agree); the others stand by and send nothing.
4. Every time a process becomes the leader — at start, after a deploy, after taking over — it runs the startup
   recovery before anything else: closes interrupted cycles, reconciles the account, positions and open orders
   with Alpaca, brings the execution ledger up to date, and runs the startup audit (paper account, endpoint, key,
   environment, kill switches, clock).
5. Each cycle then checks the market and the data; orders pass the Brain's pre-trade audit, the risk engine and
   the last gate (switches, kill switches, lease, reconciliation, health, the market still open, not shutting
   down) immediately before they leave.

### Alerts (with `QP_ALERT_NTFY_URL` / `QP_ALERT_WEBHOOK_URL`)

Sent on changes, never for a normal skipped trade: Brain stopped (also reported by a standby when the leader
holds the lease but stopped ticking), the lease lost to another process, a takeover after a crash, database
failing, Alpaca unreachable, reconciliation failed, stale data halting new positions, an unexpected position, a
kill switch turned on, an execution anomaly (repeated rejected/failed/unknown orders turn the Brain kill switch
on), three Brain cycles failing in a row, autonomous execution blocked for ten minutes in the session, an unexpected
option position, an option approaching expiration or a close that is still pending, a structural market change
detected by the Market Evolution Monitor, an option strategy promoted or demoted — and a note when each recovers.
`QP_HEARTBEAT_URL` covers the one failure a server cannot report: itself being gone.

## Logs (Render → quantpulse-api → Logs)

Every line is JSON with an `event`: `app.startup`, `app.database.waiting`, `app.shutdown`, `app.stopped`,
`supervisor.elected` / `supervisor.standby` / `supervisor.lost` / `supervisor.takeover`, `supervisor.tick`,
`brain.cycle`, `brain.decision`, `brain.risk_rejection`,
`brain.data_quality_halt`, and `trading.<kind>` for every trading event (`trading.order_submitted`,
`trading.order_filled`, `trading.order_rejected`, `trading.reconciliation_completed`,
`trading.brain_kill_switch_activated`, `trading.alert`, …). Search for an event name in Render's log search. Keys,
secrets, tokens, passwords and the database password are masked in every line.

## Remaining limitations

* The free dashboard sleeps; the first visit after 15 idle minutes takes ~1 minute (the Brain is unaffected). Upgrade
  it to `0.5c-512mb` ($7) to keep it awake.
* Backups: paid Render Postgres has point-in-time recovery (the past 3 days on the Hobby workspace plan, 7 on Pro)
  and logical backups you can create and download from the dashboard (kept 7 days). There is no off-site copy
  unless you download one now and then (or `pg_dump` with the External URL).
* One region (Virginia). If Render has a regional outage, the Brain stops (fail-closed) until it is back.
* Market data stays Alpaca's free IEX feed: quiet names often have stale or wide quotes, so entries are halted more
  often than with SIP. The limits are not loosened; SIP is a later, optional subscription (`QP_ALPACA_STOCK_FEED=sip`).
* No language model is configured (`QP_BRAIN_LLM_PROVIDER=none`), as on the PC.
* Options use Alpaca's free *indicative* options feed (not firm quotes). Option research is model-priced and no option
  strategy is established yet; real evidence starts with shadow trades on live quotes (see [`OPTIONS.md`](OPTIONS.md)).
